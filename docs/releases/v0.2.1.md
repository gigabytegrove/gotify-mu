# Gotify MU v0.2.1

**Release date:** 2026-09-25  
**Status:** Pre-release

Gotify MU v0.2.1 adds the managed update workflow that turns release discovery into an actual in-app updater.

## In-app updates

Administrators can now open **Settings → Software Update** and install a published Gotify MU release directly from the Web UI.

The update flow is:

1. An elevated administrator starts the update from the Web UI.
2. Gotify MU sends the selected semantic release version to the private updater helper.
3. The helper resolves the official GitHub tag and downloads the tagged source.
4. The helper builds the release container with the correct release version and commit identity.
5. The current Gotify MU container is stopped and preserved as a rollback container.
6. A replacement container is created with the current runtime configuration.
7. The replacement must become healthy before the rollback container is removed.
8. If creation, startup, or health verification fails, the previous container is restored automatically.

## Runtime preservation

The updater preserves the existing container's:

- environment variables
- published ports
- bind mounts and named volumes
- restart policy
- Docker network configuration
- additional Docker networks
- extra hosts
- DNS configuration
- container user
- working directory

Persistent application data is not replaced.

## Safety

A numbered release can be installed automatically when it is newer than the installed numbered release.

For development builds, automatic installation is only allowed when the development build commit exactly matches the commit targeted by the published release. This prevents a newer `master-*` test build from accidentally downgrading itself to an older release.

## Security

The updater helper is intentionally isolated:

- it has no published host port
- it communicates with Gotify MU over a private Docker network
- communication requires a generated shared token
- the install endpoint requires an elevated administrator session

The helper requires access to `/var/run/docker.sock` so it can replace the application container. Docker socket access is privileged host access; installations that do not want managed self-updating can omit the helper and continue to update manually.

## One-time migration for existing Docker installs

Existing installations need one manual bootstrap to add the updater helper and private control network. After that, future numbered releases can be installed from the Web UI without SSH.

## Compatibility

Gotify protocol/client compatibility and the v0.2.0 multi-user database model are unchanged.
