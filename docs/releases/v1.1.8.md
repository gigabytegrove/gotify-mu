# Monita v1.1.8

Monita 1.1.8 reduces unnecessary administrator re-authentication while keeping step-up authentication around genuinely sensitive operations.

## What changes

A normal signed-in administrator can now browse administrative pages and inspect operational state without repeatedly elevating the browser session. This includes users, audit history, security-policy values, operations, active sessions, service-account metadata, groups, integration status, automation state, connector state, update status, and Channel membership/assignment views.

Routine schedule and escalation-rule changes also remain available during the normal authenticated administrator session.

## What still requires elevation

Step-up authentication is still required for actions that materially affect security, credentials, access, recovery, or trust boundaries, including:

- deleting or changing users;
- changing Channel ownership, membership, group assignments, auto-assignment, or Channel security;
- creating/regenerating/deleting service-account credentials;
- changing groups and group membership;
- changing the server security policy;
- installing Monita updates;
- downloading full backups, staging/canceling restores, or downloading diagnostics;
- revoking sessions;
- changing integrations/connectors or regenerating/testing their secrets;
- password, MFA, and passkey management.

## Elevation duration

The default elevation window is now **4 hours** instead of 1 hour for installations using the default policy. The Web UI no longer hard-codes a one-hour duration; it uses the server's configured **Administrative re-authentication duration**.

Existing installations that previously saved a custom duration keep that configured value. It can be changed under **Security & Operations → Administrative re-authentication duration**.

Normal browser-session inactivity remains separate from administrative elevation.
