# Monita v1.1.8

Monita 1.1.8 reduces unnecessary administrative re-authentication while retaining step-up protection for sensitive actions.

## What changed

Administrative **viewing** now uses the normal authenticated admin session. You can move between Users, Groups, Audit, Integrations, Automation, Security & Operations, update status, Channel membership, and similar read-only areas without repeatedly entering credentials.

Step-up authentication remains required for actions that materially change security, access, secrets, system state, or data. Examples include changing the security policy, changing or deleting users, changing Channel ownership or membership, managing service-account tokens, installing updates, revoking sessions, backup/restore operations, and destructive changes.

## Elevation working window

The default administrative re-authentication duration is now **480 minutes (8 hours)**. The value remains configurable under **Security & Operations → Administrative re-authentication duration**.

Re-authentication now uses that configured value across local password, LDAP, OIDC, and passkey flows instead of silently falling back to a fixed one-hour window.

Existing installations that previously saved a custom elevation duration keep their saved value.

## Session lifetime

This release does not weaken the normal session timeout. Session inactivity remains independently controlled by **Session inactivity timeout**.

## Updating

Monita 1.1.2 and newer can install this release from **Settings → Software Update** after v1.1.8 is published.
