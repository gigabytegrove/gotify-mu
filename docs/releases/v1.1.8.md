# Monita v1.1.8

Monita 1.1.8 reduces unnecessary administrator re-authentication while keeping sensitive operations protected.

## Session behavior

Monita has two different lifetimes:

- **Signed-in session:** controls how long the browser remains logged in after inactivity. The default remains seven days.
- **Elevated session:** the shorter re-authentication window used for sensitive administrative actions. The default is now four hours instead of one hour.

The elevation duration configured under **Administration → Security Policy** is now authoritative across local passwords, LDAP, OIDC, and passkeys. OIDC also now uses the configured session inactivity policy.

## Read-only pages

A signed-in administrator no longer needs elevated credentials merely to view ordinary administrative state. Users, Groups, Audit, Operations, Sessions, Service Accounts, Integrations, Automation, Connectors, Plugin Catalog, Security Policy, and Channel membership/group-assignment views are readable without elevation.

Changes remain protected. Creating, editing, deleting, restoring, rotating, installing, revoking, or otherwise mutating administrative state continues to require re-authentication.

## Credential-sensitive views

Webhook URLs contain a routing secret. They are therefore redacted from normal Integration page loads. Use **Reveal URL** to explicitly re-authenticate and expose a webhook URL when needed. Backups, diagnostics, audit exports, and token creation also remain elevation-protected.
