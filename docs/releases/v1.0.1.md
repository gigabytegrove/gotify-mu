# Gotify MU v1.0.1

Gotify MU 1.0.1 fixes the managed updater transition from preview/development builds to a published release.

## Fixed

- Preview builds such as `master-local` can now be intentionally replaced with the latest published release.
- The updater UI no longer compares an installed commit SHA to GitHub's `target_commitish` field. GitHub may return a branch name such as `master` in that field, so the previous comparison incorrectly disabled the install action.
- Preview-to-release installation now requires an explicit administrator confirmation rather than being blocked outright.
- Existing data preservation, health verification, and automatic container rollback behavior remain unchanged.

## Upgrade notes

Existing `1.0.0` installations can upgrade normally through **Settings → Software Update**.

Installations still running a preview build may confirm the transition to the published release. The managed updater preserves the current runtime configuration and persistent application data and restores the previous container automatically if the replacement fails verification.
