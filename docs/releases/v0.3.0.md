# Gotify MU v0.3.0

**Release date:** 2026-09-25  
**Status:** Validated preview candidate

Gotify MU v0.3.0 adds native integrations and notification automation while retaining Gotify-compatible message delivery.

## Validation status

The v0.3.0 preview application commit `05bcd71fd8501161d6d35e41bae2dc17214f968a` has completed:

- the complete Web UI build

- the complete Docker/server build

Deployment and rollback procedures are documented in [../DEPLOYMENT.md](../DEPLOYMENT.md).

## Integrations

### Webhooks

Administrators can create named inbound Webhook URLs and route incoming JSON or plain-text requests directly to a Channel.

Webhook configuration supports:

- generated inbound URLs
- custom JSON paths for title, message, and priority
- default title and priority
- enable/disable
- URL regeneration
- one-megabyte request limit

### MQTT

Gotify MU can connect directly to MQTT brokers and subscribe to configured topics.

Supported connection schemes:

- mqtt
- mqtts
- tcp
- tls

MQTT connections support optional credentials, custom client IDs, automatic reconnect, topic wildcards supported by the broker, and JSON payloads containing `title`, `message`, and `priority`.

### Home Assistant

Gotify MU can connect directly to Home Assistant using a long-lived access token.

It can:

- subscribe to all Home Assistant events or one selected event type
- route events into a Channel
- reconnect automatically
- send events back to Home Assistant
- send a test event from the Integrations page

Saved access tokens are not displayed after configuration.

## Notification Automation

### Scheduled Notifications

Administrators can create one-time, hourly, daily, and weekly Channel notifications. Daily and weekly schedules are timezone-aware.

### Escalations

Messages can be escalated to another Channel when:

- their priority meets the configured minimum
- the configured delay expires
- nobody has acknowledged the original message

Any Channel member may acknowledge or undo acknowledgement directly from Message History.

### Quiet Hours

Each user may configure a daily quiet-hours window, timezone, and priority threshold. Messages remain in history; only lower-priority realtime notification delivery is suppressed during the quiet period.

### Digest

Each user may collect lower-priority notifications into a periodic digest while allowing higher-priority notifications through immediately.

## Compatibility

The existing Gotify-compatible application-token, client-token, REST, WebSocket, and Android notification workflows remain supported. Existing data is migrated additively.


## Deployment notes

v0.3.0 adds database tables for integrations, schedules, notification policies, digest queues, escalation state, and acknowledgements. The migration is additive, but a verified pre-upgrade backup is still required.

When validating a preview build:

1. Build with `BUILD_JS=1` and `RUN_TESTS=1`.
2. Do not stop the current server unless the full build and complete Go test suite pass.
3. Create and verify a data backup before starting the preview.
4. Preserve the old container until live validation is complete.
5. If rolling back after the new version has migrated the database, restore the pre-upgrade data backup together with the older container.

Do not run an older release against a database that has already been modified by a newer preview without restoring the corresponding pre-upgrade backup.
