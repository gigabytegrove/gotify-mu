# Monita v1.1.0

Monita 1.1.0 is the full product rebrand of Gotify MU.

## Brand

The active product name is now **Monita**.

**Notifications · Messaging · Automation**

Approved palette:

- Primary: `#2563EB`
- Blue: `#3B82F6`
- Teal: `#06B6D4`
- Slate: `#0F172A`
- Gray: `#94A3B8`

## What changed

The Web UI, sign-in experience, PWA/browser identity, documentation, release assets, release names, Docker metadata, local container naming, update worker naming, build artifact naming, and GHCR package naming now use Monita.

The normal Docker deployment now has one persistent container:

```text
monita
```

There is no persistent updater sidecar. During an administrator-requested update, Monita launches a short-lived `monita-update-worker`, applies and verifies the update, and removes the worker afterward.

## Existing installations

Application data remains under `/app/data`. Existing users, Channels, messages, tokens, integrations, plugins, and database contents are preserved.

The local migration from the old container identity to Monita requires rebuilding from the current repository and replacing the old `gotify-mu` container. The persistent host data directory is reused unchanged.

## Compatibility

Monita remains compatible with Gotify protocol clients. Compatibility routes such as `/application`, `/message`, and `/stream`, the upstream Go module identity, and required upstream `GOTIFY_*` configuration remain intact where changing them would break existing clients.

Legacy Gotify MU updater environment names remain accepted as compatibility aliases during migration.
